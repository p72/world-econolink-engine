# World EconoLink Engine（Python再実装）

論文「World EconoLink Engine v1」に書かれた、日米の月次マクロ計量モデルを再現したもの。
28本の標準化OLS方程式を、①〜⑳のブロック再帰的な順序で毎月1期ずつ解く。

**出典**：World EconoLink Engine v1 論文（note 掲載）<https://note.com/ryoya1106/n/ncad5ac10002d>

はじめての人は、考え方とコードを順に説明した [初級者向けガイド](docs/beginner_guide.md) から読むとわかりやすい。

> 元のコードベースと学習済みモデル（`models/*.pkl`）は論文に含まれていないため、**付録A（表7・表8）の式の仕様から作り直した**。
> 係数は手元のデータで推定し直すので、論文と同じ数値にはならない。

## クイックスタート

**データ（`data/us.csv`・`data/jp.csv`）は commit 済みなので、APIキーは要らない。** クローンしたら次の3行で実データの予測まで出せる。

```bash
pip install -r requirements.txt
python run.py train                                   # 28式を実データで推定 → models/*.pkl
python run.py simulate --scenario scenarios/2026-06_real.json --run-name 2026-06_real
```

`models/*.pkl` と `outputs/` は git 管理外なので、**クローン直後は `train` が必須**。省くと `simulate` は「学習済みモデルがありません」と言って止まる。

グラフの日本語には和文フォントが要る。Windows・macOS は標準で入っているものを自動で拾う。フォントの無い Linux では警告を出したうえで豆腐（□□□）になるので、`fonts-ipafont-gothic` などを入れる（`apt install fonts-ipafont-gothic`）。

### パイプラインの動作確認だけしたいとき

```bash
python run.py demo      # 合成データの生成 → 28式の推定 → 2026-02 シナリオ → outputs/ に CSV と PNG
```

合成データ（`data/synthetic.csv`）は、パイプラインが動くことを確かめるためのもので、**経済的な意味はない**。

> `demo` は `models/*.pkl` を合成データで学習した係数に上書きする。デモのあとに実データで予測するときは、先に `python run.py train` をやり直すこと。

## データを最新に更新する

同梱のデータより新しい月が要るときだけ実行する。e-Stat の appId（[無料登録](https://www.e-stat.go.jp/api/)で発行）を環境変数に設定してから実行する。

```powershell
$env:ESTAT_APP_ID = "<あなたのappId>"
python run.py fetch                                   # data/us.csv と data/jp.csv を取得し直す
python run.py train                                   # 取得し直したデータで推定
python run.py simulate --scenario scenarios/2026-06_real.json --run-name 2026-06_real
```

- `--data` を省略すると `us.csv` → `jp.csv` → `jp_manual.csv`（あれば）の順にマージされ、後ろのファイルの値が優先される。系列を手で差し替えたいときは `jp_manual.csv` に書けばよい。
- `ESTAT_APP_ID` が無いときは米国系列だけを取得する。この場合、日本側の式は推定をスキップし、シミュレーションではその変数を前期の値のまま保持する（米国ブロックだけは実データで回る）。
- 最新月は系列によって公表時期が違う。`base_date` は、すべての系列がそろっている月にする（2026-09-17時点では 2026-06）。

### データの出典

日米とも、統計機関（米製造業景況感のみ OECD）が公表した統計を使い、代理系列は使っていない。前年比やGDPギャップなど一部の系列は、公表値から計算している（下表に「→」で記載）。

#### 米国（`data/us.csv`）

FRED は、各機関の公表値をそのまま配布する経路としてだけ使っている。FRED に無い系列は BLS の API から直接取る。どちらもキーは不要。

| 変数 | 統計（取得経路） |
|---|---|
| world_oil_price | EIA WTI原油スポット価格 月平均（FRED MCOILWTICO） |
| us_short_rate / us_long_rate | FRB H.15 フェデラルファンド実効金利 / 10年国債利回り 月平均（FRED FEDFUNDS / GS10） |
| us_inflation | BLS CPI-U 全項目 **季節調整前** → 前年同月比（FRED CPIAUCNS）。BLS が公表する12か月変化率と同じ計算 |
| us_unemployment | BLS 失業率 季節調整値（FRED UNRATE） |
| us_gdp | BEA 実質GDP 前年同期比 **公表値**（FRED A191RO1Q156NBEA） |
| us_gdp_gap | BEA 実質GDP（GDPC1）と CBO 潜在GDP（GDPPOT）→ 乖離率。論文 4.1 と同じ算出方法 |
| us_manufacturing_confidence | OECD 企業景況感 製造業（FRED BSCICP02USM460S）。論文が指定している系列 |
| us_wage_growth | BLS Real Earnings 実質平均時給（民間計）→ 前年同月比（BLS API CES0500000013） |
| us_consumption | BEA 実質個人消費支出 十億ドル（FRED PCEC96） |

- 2025年10月は、米政府機関の閉鎖で BLS の CPI・失業率・実質平均時給が公表されていない。推定ではこの月を除き、シミュレーション開始時の実績は前月の値で補う。
- 実質平均時給は2006年3月からの統計なので、前年比は2007年3月から。実質個人消費（PCEC96）は2007年1月から。

#### 日本（`data/jp.csv`）

| 変数 | 統計（取得経路） |
|---|---|
| jp_short_rate / jp_usd_jpy | 日銀 時系列統計API：無担保コールO/N 月平均 / 東京市場 ドル・円 スポット 17時時点 月中平均 |
| jp_long_rate | 財務省 国債金利情報 10年（日次）の月平均。当月は途中までの平均になるので除外 |
| jp_inflation | 消費者物価指数（2020年基準）総合 前年同月比（e-Stat DB） |
| jp_unemployment | 労働力調査 完全失業率 季節調整値（e-Stat DB：景気動向指数 Lg6 の収録値） |
| jp_employment | 労働力調査 就業者数 → 前年同月比（e-Stat DB） |
| jp_job_openings | 一般職業紹介状況 有効求人数（パート含む一般）季節調整値、万人（e-Stat 公表Excel：長期時系列表_6） |
| jp_wage_growth | 毎月勤労統計 実質賃金（現金給与総額・5人以上・調査産業計）前年同月比 **公表値**（e-Stat 長期時系列表 表番号25-1 ＋ 厚労省の最新速報） |
| jp_economy_watcher | 景気ウォッチャー調査 現状判断DI（方向性）季節調整値 全国（e-Stat DB）。論文 表4 の係数に最も近くなる系列（下記「論文との対応の検証」） |
| jp_consumer_sentiment / export_volume / production_inventory / operating_profit | 消費者態度指数 / 輸出数量指数 / 鉱工業用生産財在庫率指数 / 営業利益（全産業）（e-Stat DB：景気動向指数 L6・C10・L2・C8 の収録値） |
| jp_investment | 実質法人企業設備投資（全産業）→ 前年同月比（e-Stat DB：景気動向指数 Lg3 の収録値） |
| jp_housing_starts | 建築着工統計 新設住宅着工床面積 総計 前年同月比 **公表値**（e-Stat 公表Excel：住宅着工統計 時系列表 月次） |
| jp_consumption | 内閣府 QE 実質民間最終消費支出 季節調整系列（年率・兆円） |
| jp_gdp / jp_gdp_gap | 内閣府 QE 実質GDP 季節調整系列 → 前年同期比 / 月例経済報告 GDPギャップ |
| jp_tankan_all / corporate_goods_price | 日銀 時系列統計API：短観 業況判断DI 全規模全産業 / 国内企業物価指数 総平均 |

- e-Stat の DB（getStatsData）の表が古い、または DB に対応していない統計（毎月勤労統計・一般職業紹介状況・建築着工統計）は、e-Stat の公表Excelを読む。これらのファイルIDやURLは公表のたびに変わるので、ファイルカタログ（getDataCatalog）や一覧ページから、毎回最新版を探して取得する。
- 実質賃金と住宅着工は、指数や水準から自分で前年比を計算せず、公表されている前年同月比を使う。特に実質賃金は、サンプル入替やベンチマーク更新による段差を補正した値が公表されていて、指数から計算した前年比とは最大3ポイント以上ずれる月がある。
- 実質消費支出（兆円）は、単位から判断して QE の実質民間最終消費支出を使っている。
- 短観・GDP・消費・GDPギャップは四半期データなので、月次に前方補間している（論文 5.1 と同じ）。
- 就業者数は、東日本大震災で岩手・宮城・福島の調査ができなかった2011年3〜8月の全国値が公表されていない（9月以降は補完推計値あり）。このため前年比は2011年3〜8月と2012年3〜8月が欠け、この期間は推定サンプルから外れる。
- 読み込みには `xlrd`（旧形式 .xls 用）と `openpyxl` が必要。

### 政策シナリオ3本

実データ（`data/jp.csv`・`data/us.csv`）を起点にした、政策金利だけが違う3本。基準月は全系列がそろう 2026-06、予測は 2026-07〜2027-06 の12か月。**2026-09 と 2027-01 に 0.25％ ずつ動かすか動かさないか**だけが違う。

| 月 | `2026-06_real.json`（利上げ） | `2026-06_hold.json`（据え置き） | `2026-06_cut.json`（利下げ） |
|---|---|---|---|
| 2026-07〜2026-08 | 1.00 | 1.00 | 1.00 |
| 2026-09 | **1.25** | 1.00 | **0.75** |
| 2026-10〜2026-12 | 1.25 | 1.00 | 0.75 |
| 2027-01 | **1.50** | 1.00 | **0.50** |
| 2027-02〜2027-06 | 1.50 | 1.00 | 0.50 |

- **違うのは政策金利だけ**。原油は3本とも WTI 84 ドルで固定し、`cpi_mode` も `add_factor_decay` も同じ。したがって3本の差は、まるごと政策金利の効果として読める。
- **政策金利の水準**：実績は 2026-07 が 0.978％、2026-08 が 0.977％なので、予測の起点を 1.00％ とした。変更月は、その月から新しい水準に切り替わるものとして置いている。実際には月中の金融政策決定会合で決まるため、決定月の月中平均は旧水準との間になるが、ここでは丸めていない。
- **原油の 84 ドル**は、基準月 2026-06 の実績（84.81 ドル）に近い水準での横ばい。原油の先行きは論文にもモデルにも根拠が無く、この横ばいは分析者の仮定。

比較図は次のコマンドで作る。

```bash
for s in real hold cut; do
  python run.py simulate --scenario scenarios/2026-06_$s.json --run-name 2026-06_$s
done
python tools/compare_scenarios.py 2026-06_real 2026-06_hold 2026-06_cut \
    --labels 利上げ 据え置き 利下げ --note-file tools/notes/policy_paths.txt \
    --out outputs/compare_policy.png
```

シナリオは2本以上なら何本でも並べられる（配色のスロット数から最大8本）。パネルは `--panels` に列名を並べて差し替えられる（`--list-vars` で使える列名の一覧が出る）。図の高さはパネル数と注記の行数から決まるので、増減させてもはみ出さない。

```bash
# 例：日米の実質GDPと失業率だけを見る
python tools/compare_scenarios.py 2026-06_real 2026-06_hold 2026-06_cut \
    --labels 利上げ 据え置き 利下げ --panels jp_gdp us_gdp jp_unemployment us_unemployment
```

2027-06 時点の結果：

| 指標 | 利上げ | 据え置き | 利下げ | 利上げ − 利下げ |
|---|---|---|---|---|
| 政策金利(%) | 1.50 | 1.00 | 0.50 | +1.00 |
| CPI 前年比(%) | 2.76 | 3.41 | 4.05 | **−1.29** |
| 実質GDP 前年比(%) | 0.15 | 0.20 | 0.25 | −0.10 |
| GDPギャップ(%) | −1.45 | −1.38 | −1.31 | −0.14 |
| 完全失業率(%) | 2.91 | 2.89 | 2.86 | +0.05 |
| 長期金利(%) | 3.42 | 3.47 | 3.52 | −0.10 |
| USD/JPY | 167.3 | 169.5 | 171.7 | −4.37（円高） |
| 実質消費支出(兆円) | 304.1 | 304.9 | 305.8 | −1.69 |

3本は全指標できれいに単調に並び、利上げ側と利下げ側の効果はほぼ対称（この金利幅では反応がほぼ線形）。物価への効き（政策金利 1.0pt に対して CPI 1.29pt）に比べると、実体経済側（実質GDP 0.10pt、失業率 0.05pt）の反応は一桁小さい。

長期金利だけは**利上げのほうが低く、利下げのほうが高い**：長期金利の式は物価の影響を強く受けるため、利上げによる CPI の下振れが政策金利の上昇分を打ち消す。住宅着工は利上げで増える向きに出るが、この式は当てはまりが弱い（R² 0.17）。

**名目GDP は出せない。** 28式が扱うのは実質GDP前年比（`jp_gdp`・`us_gdp`）とGDPギャップで、GDPデフレーターの式が無いため名目値は計算されない。CPI を代わりのデフレーターにするのは、対象の範囲が違う（CPI は輸入物価を含み、設備投資や政府支出を含まない）ので妥当でない。

## 論文からの補完・拡張

- **論文に書かれていない細部の補完**
  - `us_wage_v1` の「FF金利(当期)」は、FF金利が③で後から決まるため t−1 にした。
  - 実質政策金利は「政策金利 − CPI前年比」とした。ドル円の式の「日米金利差」は10年債利回りの差（米 − 日）、「日米実質金利差」は実質政策金利の差（米 − 日）、景気ウォッチャーの式の「実質政策金利差」は（日 − 米）とした。「log(CPI+3)」のCPIは前年比と解釈した。
  - inflation_premium／risk_premium の分解式と gdp_per_worker（実質GDP前年比 − 就業者数前年比）は論文に計算式が無いので、`variables.derive()` で独自に定義した。
  - 景気ウォッチャーは、すべての式で現状判断DI（方向性・季節調整値）を使う。消費の式は論文で「現状判断水準」と書かれているが、状態変数は1つだけで、同じ表現の GDPギャップ式は方向性DIで表4に一致するため（下記「論文との対応の検証」）。
- **循環カットの自動検査**：ある式が、まだ計算されていない変数の当期値を参照すると、`CircularReferenceError` になる。
- **出力は PNG**：論文の PDF ダッシュボード（9章）の代わりに、同じ8パネル構成の PNG を書き出す。グラフの日本語は、`exporter.py` の `JP_FONT_CANDIDATES` を Windows → macOS → Linux の順に探して、最初に見つかったフォントを使う。1つも無いと警告を出したうえで豆腐（□□□）になるので、その場合は `fonts-ipafont-gothic` や Noto Sans CJK JP を入れる。
- **履歴バッファ**：論文は実績12期分を先頭に置くが、t−13 などのラグを直接参照できるよう24期分を持つ（出力は実績12期＋予測期）。
- **アドファクター（`add_factor_decay`、既定はオフ）**：基準期の残差（実績 − 当てはめ値）を、`decay^h` で減らしながら各式に足す。AR項を持たない水準式（米個人消費・FF金利など）では、予測1期目に実績から当てはめ値へ段差のように跳ぶことがあり、これを抑える。
- `statsmodels.api` は環境によってDLLの読み込みでブロックされることがあるため、OLS関連のモジュールだけを直接importしている。scikit-learn は使わず、`StandardScaler` を自前で実装した。

## 論文との対応の検証

係数が論文に載っているのは、GDPギャップの式（表4）だけ。同じ推定期間（2007年1月〜2025年1月、N=217）で推定し、データの選び方を比べた結果が次の表。

| データの組み合わせ | 定数項 | 景気ウォッチャー | 輸出数量 | 米GDPギャップ | R² | DW |
|---|---|---|---|---|---|---|
| 論文 表4 | −0.464 | 0.633 | 0.916 | 0.790 | 0.715 | 0.848 |
| **現状判断DI（方向性・季調）＋内閣府GDPギャップ（採用）** | −0.477 | 0.750 | 0.922 | 0.846 | 0.761 | 0.916 |
| 現状判断DI（水準）＋内閣府GDPギャップ | −0.477 | 0.979 | 0.909 | 0.604 | 0.811 | 1.130 |
| 現状判断DI（方向性・季調）＋日銀 需給ギャップ | −0.134 | 0.446 | 0.154 | 0.859 | 0.669 | 0.438 |
| 3つ目の変数を日本GDPギャップ(t−1)にした場合 | −0.477 | 0.502 | 0.312 | 1.323 | 0.865 | 1.867 |

- 表4の「GDPギャップ(t−1)」は、本文・付録どおり米国のGDPギャップと判断できる（日本のギャップにすると輸出の係数が大きく外れる）。
- 残る差は、公表後のデータ改定による違いと考えられる。

論文から式を再現する際の注意点：

- 付録の米国ブロックの表（表7）は、PDF上で右端が切れている。切れているのは各セル1行目の末尾数文字だけなので、説明変数の構成は復元できる。
- 付録の見出しは「主な説明変数」なので、載っていない変数があった可能性は残る。ラグの記載がない説明変数は当期として実装した。
- 論文の中で食い違っている箇所は、付録（表7・表8）を優先した。
  - 表6：日本CPIの短観DIラグ t−6、輸出数量の在庫率ラグ t−3、米賃金の景況感ラグ
  - 7.2節：長期金利の式に gdp_per_worker
- 論文との意図的な違い：ドル円（論文は yfinance の JPY=X）とWTI原油（論文は yfinance の CL=F 先物）は、公式統計（日銀の月中平均、EIAのスポット価格）を使っている。
